Command Center

A home screen that answers one question for a car salesperson: what should I actually do today? I started it, rebuilt it, shipped it, and it went out to every dealership in March 2026.

THE PROBLEM

Everything was already there. None of it was in one place.

A dealership already had the answers: who is ready to buy, whose offer expires on Friday, who was on the website last night, whose car is booked in for a service next week. The problem was that each of those lived on a different screen.

So a salesperson started every morning by guessing. The brief was not to build another dashboard — there were enough of those. It was to put the day in front of them in one list, sorted so the top of it is where they should start.

Two things worth telling

01 — I THREW AWAY A DAY’S WORK IN A DAY

The first version was elegant and wrong

My first build modelled the five kinds of update as five separate pieces of state, with the list of categories baked into the type system. It was tidy TypeScript and it compiled beautifully.

It was also wrong. Adding a sixth category meant editing the state, the reducer and every place that read from it. Later the same afternoon I deleted all five and replaced them with one flat list driven off a table. Nothing from the morning survived except the routing.

Noticing your own design is too rigid on day one costs an afternoon. Noticing it in month three costs a rewrite and an argument.

02 — THE BADGE THAT LIED

“47 customers” that turned into 31

Each tile showed a count. The count was the number of rows we had, not the number of actual people — the same customer could appear three times, and one placeholder record with an all-zeros id was being counted too.

So the badge promised more than the list delivered. Click it and you would find fewer names than the number you clicked on. I moved the de-duplication upstream so the count and the list are derived from the same filtered set, and pinned every rule with its own test — including two that assert the screen does nothing when the store code is missing, rather than blanking the panel.

A number a salesperson cannot trust is worse than no number at all.
