What I actually do with AI

Three times a model genuinely took work off someone. And once when I decided it shouldn’t.
It writes the follow-ups

Reps used to write every call script and email from scratch. Now it drafts them, in over a hundred languages. Most of that service is mine, and the good part isn’t the model call. It’s the rules keeping it off claims a manufacturer’s lawyers would hate, and the step that strips the customer’s vehicle number before anything leaves.

Announcement
It writes the day’s list

Three agents in a chain, then a fourth one marks the result out of ten. Under seven and it never ships. QA write their own scoring rules now, which means the quality bar isn’t waiting on me to change code.

Ask the warehouse in English

Someone non-technical asks a question in plain words, gets a chart back, skips the analyst queue. The bit worth knowing: you can’t trust the query the model wrote, not the sentence the person typed. So that’s what gets checked before anything runs.

And once, no model at all

Upgrading 2,455 files to a new React. I wrote eleven thousand lines of tooling that reads the code properly instead. This problem has exactly one right answer, and a model would get it wrong often enough that nobody would notice until production.

If you can’t tell whether the output is any good, you don’t have a feature. You have a demo. So I build the thing that marks it at the same time as the thing that writes it.

When nobody’s paying me

I learn things by rebuilding them badly first. At the moment that’s a search system over old Gujarati books, the ones printed before Unicode existed, so what you see on the page and what’s in the file are two different things. The encoding mess is the actual project. Search is just the excuse.

Everything up there is half-finished with notes on where it broke. That’s on purpose.
