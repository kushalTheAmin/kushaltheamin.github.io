02

A pipeline that grades its own output

Three agents in a chain write customer-segment messages; a fourth scores them 1–10 against a typed contract — semantic connection, actionability, jargon detected as a list rather than a boolean — with a below-7 failure threshold. A custom-criteria hook lets QA author new evaluation rules without a code change.

Wiring an API call is the easy half. Building the thing that decides whether the output is good enough to ship is the part that is actually hard.

04

Agentic natural language → SQL

Non-technical users query production BigQuery in English. Five declared tools in AUTO mode, a genuinely recursive agent loop, and self-healing queries that re-prompt for alternative SQL on error or zero rows.

The security model points at the right threat. Layer one screens the user's English. Layer two compiles seventeen forbidden keywords against the model's generated SQL — in a text-to-SQL system the untrusted artifact is what the LLM wrote, not what the user typed. Spend is gated by a dry-run byte estimator before anything executes.

How I work

THREE HABITS, WITH RECEIPTS
01  /  MEASUREMENT

Measure it, or it isn't real.

Nobody asked for the LLM observability layer. I built it across three repositories — new activity types in the org-wide entity model, gateway logging on every AI endpoint, and a 1,787-line metrics dashboard over BigQuery — and was then named the accountable engineer for token and cost figures in the company's formal technology governance review. Building the measurement layer is what put me in that seat.

02  /  SAFETY

Fail closed by default.

Behavioural drivers are withheld from the prompt unless the deal is genuinely matched — undefined means restricted, pinned by a test named for exactly that case. The VIN is kept for the audit log and never reaches the model. The offer link is withheld when the payment delta breaches marketing compliance, and the model is told why it is missing so it does not generate around a hole. None of that was in the requirement.

03  /  REVIEW

Attack the design before writing it.

Before implementing the RAG briefing service I ran three validation rounds of four agents against my own design and resolved fifty-plus issues, thirteen of them critical in round one alone: a cache key that was not globally unique, a retry policy that would have multiplied model calls on timeout, a safety config that is not valid Vertex. All cheaper to find there than in review.
