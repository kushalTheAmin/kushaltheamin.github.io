01  /  THE PROBLEM

Anyone who has “worked with LLMs” can wire an API call. The hard question is the one after it: is this output good enough to show a customer?

Generated insight messages go to dealership salespeople who act on them. A message that is fluent but does not actually connect to the customer segment it was generated for is worse than no message — it burns the salesperson's trust in the whole feature. “Looks fine to me” does not scale to eighteen segments across thousands of dealers, and it is not something a QA function can own if the only way to change the standard is a pull request.

02  /  THE PIPELINE

Four components, each with a single job. The orchestrator coordinates; the evaluator is a separate agent with its own prompt, so the thing that scores the message is not the thing that wrote it.

03  /  WHAT “QUALITY” MEANS

Quality is defined as a contract, not a vibe. The evaluation model returns a typed object, and each field was chosen because a specific failure mode needed catching.

Score One to ten, with a below-seven failure threshold. A number, so it can be tracked over time rather than argued about.
SemanticConnection Does the message actually connect to the segment criteria it was generated for? This is the failure that fluency hides.
ContextualPhrases Each phrase classified good, questionable or bad — three states, because most borderline output is neither clearly fine nor clearly wrong.
JargonDetected A list, not a boolean. “Contains jargon: true” tells you nothing you can fix; the list tells you which words to prompt against.
Actionability Can a salesperson actually do something with this? The whole feature is worthless if the answer is no.

04  /  TWO DECISIONS

QA owns the criteria, not engineering

The evaluation request exposes a custom-criteria hook. QA authors a new rule and runs it — no code change, no deploy, no waiting on me. Handing the definition of “good” to the people who actually own quality is what stops the eval harness from rotting the moment its author moves on.

Temporal spread by default

When no dates are supplied the harness samples fifteen across the year rather than defaulting to today. An eval run that only ever tests one good day is an eval run that will pass forever and tell you nothing.

Most engineers who work with LLMs can wire an API call. Building the thing that decides whether the output is good enough to ship — and then handing the criteria to QA so it is not gated on engineering — is the part of applied AI that is actually hard.
