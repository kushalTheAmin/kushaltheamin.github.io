The year I learned a chart is mostly geometry

Started September 2018. Three months later Cigna bought the company, and what came out of it was Health Connect 360: prescriptions, medical records, lab work and wearable data, finally in one place.

Everything new at once

I finished at Express Scripts that January and started at Bank of America the same month, on a forecasting tool the bank’s traders used every day. New framework, new language, new industry, all in the same week. Angular, RxJS, Java, and a corner of finance I knew nothing about.

RxJS is the one that changed how I think. You stop writing “when this happens, do that” and start describing a stream of values arriving over time, which is exactly what a screen full of moving numbers is.

Honestly though, the framework was the easy part. Going from healthcare to trading was the hard bit.

Most of the year then went into building it for real: a .NET service running streaming inference against Gemini on Vertex AI, with response caching and conversation archiving behind it.

Applied AI, specifically

A bit more on what that has actually involved. Open one.
01 Production LLM applications

Fritz is the one that is live, on every customer’s deal sheet, in over a hundred languages. Streaming inference against Gemini on Vertex, response caching, conversation archiving, the lot.

Most of the interesting work was the unglamorous half. Per-manufacturer rules that keep it away from claims a legal team would object to, and a step that strips the customer’s vehicle number before anything reaches the model. That one has a test named after it, so it does not quietly disappear in a refactor.

.NET Gemini / Vertex AI Streaming inference Redis GKE
02 Evaluation, and knowing when output is good enough

Generated messages get marked out of ten by a separate model with its own adversarial prompt, against a typed contract. Does it connect to the segment it was written for. Is there jargon, as a list rather than a yes or no. Can a rep actually act on it. Under seven and it does not ship.

QA write their own criteria through a hook, so the quality bar can move without waiting on a code change.

LLM-as-judge Typed scoring contract Sampling across dates BigQuery
03 Agents and tool use

Three agents chained for the daily suggestions: one works out who the customer is and what situation they are in, one writes, one marks. Separately a text-to-SQL agent with five declared tools in auto mode and a genuinely recursive loop, where what gets validated is the query the model wrote, not the sentence the person typed.

On my own time, a multi-agent research system set up so the scorer cannot flatter the writer: five specialists per round, an independent devil’s advocate, and an auditor prompted to resist score inflation.

Multi-agent Function calling LangGraph asyncio Anthropic SDK
04 Automating the repetitive parts

Skills and spec-driven development, so the repetitive parts of the work are written down once and run the same way twice. Same instinct as the product side: if someone is about to do the same thing two thousand times, that is a tool rather than a task.

And where a model is not the right answer, not reaching for one. Moving 2,455 files onto React 19 took eleven thousand lines of tooling that reads the code properly, because that problem has exactly one right answer and a model would get it wrong quietly.

05 Learning it in public

Most of this I first built badly somewhere public. Retrieval from scratch over Gujarati books printed before Unicode existed. Multimodal agents with LangGraph and Gemini. Transcription and summarising, with tests. A job search automated onto Cloud Functions because doing it by hand got dull.

It is on GitHub with notes on where it broke.

RAG Whisper LangGraph Vertex AI GCP

If you can’t tell whether the output is any good, it is hard to call it a feature. So the thing that marks it gets built alongside the thing that writes it.

When nobody’s paying me

All of it public, most of it half-finished

I learn things by building them badly first, then writing down where they broke. Before any of this I spent six years building Sampark for a local non-profit, an app real people used for event management and live data tracking, which taught me that shipping to people you will run into on a Sunday is its own kind of pressure. These are the ones I’d show someone now.
